# RCA — giguiya-eventi (run 482f8ab5-784d-4b4f-90ba-2783e8e0c2cd)

## Symptom
Initial deploy failed at step **deploy_k8s**: "deployment failed to become ready: timed out waiting for the condition." Rollout logs show the backend crashing on startup:

```
ERROR:    Application startup failed. Exiting.
OSError: Multiple exceptions: [Errno 111] Connect call failed ('::1', 5432, 0, 0), [Errno 111] Connect call failed ('127.0.0.1', 5432)
...sqlalchemy/dialects/postgresql/asyncpg.py...
File "/app/backend/server.py", line 18, in lifespan
Backend died, shutting down nginx...
```

## Root cause (CONFIRMED — inspected source in eph sandbox)
The app is built on **PostgreSQL via SQLAlchemy + asyncpg**, but the Emergent platform provisions **MongoDB only**. There is no PostgreSQL server in the production pod, so the boot-time DB connection is refused and the backend dies — nginx then exits and the pod never reaches Ready, timing out `deploy_k8s`.

Specifics found in the pulled source:
- `backend/app/core/database.py:6` → `engine = create_async_engine(settings.DATABASE_URL, pool_pre_ping=True)`
- `backend/app/core/config.py:10` → `DATABASE_URL = os.environ["DATABASE_URL"]` (required at import)
- `backend/server.py:16-19` → `lifespan` runs `async with engine.begin() as conn: await conn.run_sync(Base.metadata.create_all)` on startup → forces a live Postgres connection before the app can serve.
- All ORM models (`auth`, `project`, `member`, `user`, `booking`, `event`) and every router/service use `sqlalchemy ... AsyncSession`.
- `backend/.env` ships `DATABASE_URL="postgresql+asyncpg://giguiya:giguiya_pg_2026@localhost:5432/giguiya"`. This custom key was seeded into the production Secrets from the preview `.env` on first deploy, so prod points `DATABASE_URL` at `localhost:5432` — which only existed in the preview environment, not in the production pod.
- Template is `fastapi_react_mongo_shadcn_base_image` (MongoDB). `motor`/`pymongo` are present in requirements.txt but the data layer does not use them.

This is NOT fixable by a deployment manifest (there is no Postgres endpoint to point at) and NOT a transient/infra issue. A re-run with no source change will fail identically.

## Suggested fixes (one of the two)
1. **Code (recommended, E1):** Migrate the data layer to the platform-provided MongoDB. Replace the SQLAlchemy/asyncpg engine, ORM models, and session usage with `motor` against `MONGO_URL`/`DB_NAME` (both already injected as system secrets). Remove the blocking Postgres connect in `server.py` `lifespan`. This aligns the app with the MongoDB template it was deployed on.
2. **User (alternative):** Provision an externally reachable managed PostgreSQL (e.g. Neon/Supabase/RDS — not localhost) and set `DATABASE_URL` in Deployment Panel → Secrets to that reachable connection string, then redeploy. A `localhost:5432` value can never work in production.

## What I did NOT do
No manifest change and no resume — neither can resolve a missing database backend. Handing back to E1 for the source fix.
