### Blocker 2 (confirmed, would fail even with credits): backend targets PostgreSQL, but the platform only provisions MongoDB
The committed run actually reached the **deploy** step and failed because the backend crashes on startup:

```
OSError: Multiple exceptions: [Errno 111] Connect call failed ('::1', 5432, 0, 0),
                              [Errno 111] Connect call failed ('127.0.0.1', 5432)
  File "/app/backend/server.py", line 18, in lifespan
    async with engine.begin() as conn:
ERROR:    Application startup failed. Exiting.
Backend died, shutting down nginx...
```
Pod never becomes Ready → `k8s deploy: deployment failed to become ready: timed out waiting for the condition`.

Evidence from the run's own source (verified in an eph sandbox):
- `backend/server.py` line 17–19 `lifespan` opens a SQLAlchemy async engine at startup (`async with engine.begin()` + `Base.metadata.create_all`).
- `backend/app/core/database.py`: `engine = create_async_engine(settings.DATABASE_URL, ...)`.
- `backend/app/core/config.py`: `DATABASE_URL = os.environ["DATABASE_URL"]` (required).
- `backend/.env`: `DATABASE_URL="postgresql+asyncpg://giguiya:...@localhost:5432/giguiya"`.
- `requirements.txt` carries both stacks: `asyncpg`, `SQLAlchemy` AND `motor`, `pymongo`.

This is an **architecture mismatch**: the app was built on the FastAPI+**MongoDB** base image (the platform provisions MongoDB Atlas and injects `MONGO_URL`/`DB_NAME`), but the code ignores Mongo and connects to a **PostgreSQL** server on `localhost:5432`. No Postgres exists in the production pod/cluster, so the connection is refused and the backend exits. On first deploy, the custom `DATABASE_URL` is seeded from the preview `.env` (the localhost Postgres URL), which can never resolve in prod.

## Fixes
1. **User — add credits.** Balance is 22.67, deploy needs 50. Top up in the billing panel before redeploying.
2. **Code (E1) — resolve the DB mismatch.** Either:
   - (Recommended) Migrate the data layer from SQLAlchemy/asyncpg/Postgres to **MongoDB + Motor** (already in requirements), driven by the platform-provided `MONGO_URL` / `DB_NAME`. Remove the Postgres `engine.begin()` / `create_all` call in `server.py` lifespan and the `DATABASE_URL` requirement in `config.py`; OR
   - Keep Postgres but point it at an **externally reachable managed Postgres** — then the user must provision that DB and set `DATABASE_URL` in Deployment Panel → Secrets to the external host (NOT localhost:5432). The managed base image will not run a Postgres sidecar.

Note: credits (Blocker 1) is the user's to settle; the DB code change (Blocker 2) is an E1 source fix — neither is fixable from the deployer agent, and neither is a manifest issue.
